# LiveToFrame 跨平台产品与工程规范

适用范围为 iOS 和 Android 的相册浏览、批量保存与原件处理。两端统一的视觉和交互实现标准见 [跨平台视觉与交互设计规范](跨平台视觉与交互设计规范.md)；Android 的机型和阶段见 [Android 首版构建计划](Android-首版构建计划.md)。

2026-11-17 修订。选片、提交、保存结果和中断恢复以本文为准。

打开 [双平台 HTML 交互原型](LiveToFrame-Prototype.html)，在页头切换 iOS 和 Android。页面内附本轮设计修订说明。

## 工程入口

| 平台 | 工程入口 | 命令行构建 |
| --- | --- | --- |
| iOS | 用 Xcode 打开 [ios/LiveToFrame.xcodeproj](../ios/LiveToFrame.xcodeproj)，源码和测试也位于 `ios/` | 从项目根目录运行 `xcodebuild -project ios/LiveToFrame.xcodeproj -scheme LiveToFrame -destination 'generic/platform=iOS' build` |
| Android | 用 Android Studio 打开 [android/](../android/)，应用模块位于 `android/app/` | 进入 `android/` 后运行 `./gradlew :app:assembleDebug` |

## 产品与交互

| 规则 | 验收方式 |
| --- | --- |
| 手机网格固定五列，提供「按日 / 全部」 | 点选一张后往返切换，图块勾选、分组计数和底栏张数一致。双指动作不改变列数。 |
| 相册已显示的照片可以立即操作 | 整库仍在读取时，已显示的照片可点选、按日选择和提交保存。首次显示优先读取最近照片；重复打开复用有效的识别结果。记录首批显示和全量读取两项耗时。 |
| 按日操作以点击时的展示范围为准 | 先应用访问权限、收藏保护及当前筛选。识别完成的日期显示「选当天 / 取消当天」；仍在识别的日期显示「选已加载 / 取消已加载」。后续补入的照片保持未选。跨日期选择、切换「按日 / 全部」及筛选时，当前会话的有效勾选保持。 |
| 未提交的选择只存在于本次运行 | 前后台切换、切换视图和打开预览保留勾选。结束进程后重开，照片勾选、张数和估算从空状态开始。撤销访问或资产消失后剔除无效勾选。底栏「取消选择」一次清空当前勾选。 |
| 提交时冻结本次保存范围 | 以确认时的有效已选照片为准。提交成功后，这些照片从相册勾选中清空；扫描后续发现的照片保持未选。已提交批次仍按操作记录核验和恢复，重启后通过结果入口继续处理。 |
| 点按和长按互斥 | 点按切换选择，长按预览并自动播放一次。关闭时回到原视口并保留选择。辅助功能可独立触发预览，读出选中态。 |
| 清单、估算与实际保存使用同一批资产 | 有隐藏的有效已选项时先展示清单。收藏默认保护，启动前再次核对。权限和覆盖范围明确可见。 |
| 有勾选时启用「只看已选」 | 清空或取消最后一个勾选时，退出「只看已选」并禁用该按钮，恢复当前筛选下的相册列表。 |
| 空间估算有独立的状态 | 已知、部分已知、全部未知分别显示。计算中保持金额区和底栏尺寸。文案说「移除后预计减少」，本机回收站、系统实际占用和云端容量分别核对。 |
| 结果页显示实际状态和下一步 | 逐张结果以只读方式显示状态。集中入口通过副本资产 ID 读取本批副本，展示系统相册位置。核对原件的入口标红，最终移除由系统确认。存在未完成的操作时，在结果页提供当前支持的核验或续跑入口。 |

## 两端实现对照

| 规则 | iOS | Android | 对齐状态 |
| --- | --- | --- | --- |
| 读取期间操作 | PhotoKit 查询实况资产并生成日期分组，结果返回一次显示；已有列表可在刷新期间继续操作 | 逐批读取 MediaStore 查询结果，边识别边显示；已展示范围可选择和保存 | 操作规则已对齐，加载方式随系统接口不同 |
| 勾选与结果 | 去掉上次选择的恢复；提交后清空勾选，逐项展示结果 | 去掉上次选择的恢复和「保存批次结束」；提交后清空勾选，逐项展示状态 | 已在两端源码对齐 |
| 首次照片权限 | 由授权页按钮打开系统权限框 | 首次无权限时自动打开系统权限框 | 入口触发不同；两端都仅查询授权范围 |
| 保存前核对 | 存在被场景筛选隐藏的已选照片时打开清单；其余可直接保存 | 每次保存先打开核对清单 | 待统一为隐藏已选时核对 |
| 保存顺序 | 按点选顺序 | 按相册列表顺序 | 待统一；两端的张数和资产范围应与核对清单一致 |
| 收藏保护 | 首次及每次重开默认开启；本次运行可关闭 | 首次默认开启，记住上次设置 | 待统一设置是否跨重启保留；收藏原件的移除资格也需统一 |
| 中断后继续 | 恢复逐张写入记录，对已有副本重新核验；未开始项需要重新选片 | 结果页可继续上次批次，复用已核验的副本 | 勾选与任务记录分离已对齐；iOS 尚缺整批续跑 |
| 格式、相册和筛选范围 | PhotoKit 实况资产、相册归属迁移、端侧场景筛选 | 当前识别本机相机 JPEG，副本保存到 `Pictures/LiveToFrame/` | 平台能力差异，按实际覆盖范围展示 |
| 估算及结果字段 | 依据配对视频大小，结果含拍摄时间、文件名及独立副本查看 | 读取 JPEG 动态段长度，结果以文件名、状态和回读详情为主 | 需统一估算既有副本时的空间口径及结果字段；各项未知要显式展示 |

## 转换与原件保护

1. **确认封面和数据范围。** 优先解析能证明是当前封面的静态编码。检查尺寸、方向、色彩、HDR、拍摄时间与位置，以及平台能表达的收藏和相册归属。格式或封面无法确定时跳过；可用的降级导出单独标明。
2. **先保存，再回读。** 写入前保存操作 ID、原件 ID 和版本或指纹。写入取得副本 ID 后更新记录。回读核验真实副本可打开、没有动态资源且满足对应格式的保真条件。系统接受写入请求和完成核验分别显示。
3. **单独复核移除。** 用户从结果页主动打开核对清单后，重新核对源、副本、访问权限、收藏、对应相册归属及平台可移除条件。保存阶段可检查源资产状态，要求已有已核验副本的检查留到移除阶段。只将通过复核的项目提交系统确认。取消、待核验、失败或无法确认结果时保留原件或标为待核对，结果只报告已确认发生的状态。
4. **中断恢复按操作 ID 对账。** 优先查询已有副本再继续。当前操作结果不明确时停在待核对，避免重复写入。同一操作重试和用户明确发起新一批保存分别处理。原件与副本均按平台资产 ID 识别，用户可见文件名优先保留相机原名。
5. **控制批处理资源。** 相册查询、文件处理和编码核验在后台执行。惰性加载缩略图，缓存与资产版本关联；同一批串行处理或使用有界并发，避免连续刷新和无界解码。计时分准备、写入、回读三段。
