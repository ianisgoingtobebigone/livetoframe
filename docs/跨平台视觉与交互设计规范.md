# 实况转静态｜跨平台视觉与交互设计规范

版本：1.1 · 日期：2026-11-22  
适用范围：LiveToFrame iOS 与 Android 手机端相册浏览、选片、静态副本保存、结果核验和原件处理。  
本文记录验收规则。已确认的 [双平台 HTML 原型](LiveToFrame-Prototype.html)提供视觉和交互参照；设备差异、工程落点和验证记录见[改版对照与实施清单](跨平台界面改版对照与实施清单.md)。

## 1. 产品目标与设计原则

本应用帮助用户从实况照片创建可独立查看的静态副本，并在用户主动确认后处理原件。主流程必须明确区分「保存静态副本」和「移除实况原件」：保存不改变原件；移除必须发生在副本保存与核验之后，并由系统确认。

1. 照片是相册页主体。工具栏简洁，主要操作保持在当前页面可达。
2. iOS 与 Android 共享相同的信息架构、文案、色彩语义、控件样式、尺寸基线和操作规则。
3. 只有系统导航、权限、媒体选择、删除或回收站确认等平台规范要求的部分采用原生差异；不得以“平台风格”为由任意改造普通按钮、分段、间距或布局。
4. 所有破坏性操作清楚标红，并在系统确认前重新核验目标。颜色不能替代文字说明。
5. 照片加载、选择、保存、核验和清理状态都应有明确反馈。不可操作的入口使用真正的禁用状态。
6. 适配小屏、系统字号、屏幕安全区和辅助功能。不可为塞入内容而缩小文字或触控目标。

## 2. 跨平台一致性规则

| 内容 | 两端统一规则 | 允许的平台差异 |
| --- | --- | --- |
| 页面结构 | 相册页、保存进度、结果页、副本查看、核对清单的顺序和层级相同 | 状态栏、安全区、系统返回手势按系统实现 |
| 页面标题 | 相册页标题固定为「实况转静态」；页面下方标题和操作文案逐字一致 | 返回控件外形、系统导航栏由平台决定 |
| 相册视图 | 同一行显示「按日 / 全部」分段；默认按日；照片网格固定五列 | 无 |
| 普通控件 | 分段、筛选按钮、文本按钮、选择样式、主次按钮、卡片和状态标签共用尺寸和视觉语义 | 仅由系统接管的确认框可使用原生外观 |
| 选择反馈 | 浅色蒙版加蓝底白勾；照片边缘保持原样；数量、分组计数、底栏状态同步 | 触控反馈和辅助功能沿用平台行为 |
| 加载与异常 | 状态定义、文案、重试入口和原件保护规则一致 | 加载策略可按 PhotoKit / MediaStore 的返回方式调整，不改变用户可操作规则 |
| 结果 | 一份只读的逐张结果列表；查看静态副本为主要操作，原件处理独立展示 | iOS 删除、Android 移入回收站分别交给系统确认 |

开发时先复用统一设计 token 与组件。平台分支只允许包住确有系统差异的代码；若新增分支改变颜色、尺寸、文案或操作路径，必须说明对应的系统规范原因。

## 3. 设计 Token

### 3.1 单位与布局

- iOS 使用 pt，Android 使用 dp；下列数值在两个平台按同一逻辑尺寸实现。文字按平台系统字体度量，尺寸和字重保持接近。
- 页面内容左右边距：16 dp/pt；紧凑宽度可降至 12。安全区必须由系统 inset 处理。
- 常用间距：4、8、12、16、24。优先使用 8 的倍数；照片格间距 4。
- 顶部导航栏高度：52；水平布局。相册标题左对齐，不另设大块首屏介绍卡。
- 底部操作区固定在安全区内，内容滚动时保持可见；滚动内容不得被其遮挡。
- 手机相册网格固定五列、等宽、正方形、间距 4，缩略图使用中心裁切。宽度变化时只改变单格尺寸，不改变列数。
- 结果缩略图 43 × 43，圆角 8；结果行最小高度 59，内容间距 10。
- 功能操作行最小高度 55；弱表面分组圆角 11。
- 主要圆形或图标操作触控区域至少 44 × 44；按钮高度至少 44，主按钮高度 46。
- 底部弹层顶部圆角 25，按内容与屏幕高度调整，长内容独立滚动，底部动作始终可达；可保留系统原生拖拽指示。
- 日期快滚以叠层覆盖在图库右侧。网格左右使用同一页边距，滚动条的显示状态不改变第五列的位置和尺寸。把手外观参考 33 × 46 的胶囊，触控区域约 39 × 48，日期浮标在把手左侧。
- 页面、底栏、弹层与系统安全区衔接；键盘弹出时保证当前输入和主操作可见。

| --- | --- | --- |
| `surface` | `#FFFFFF` | 页面、底栏、弹层、分段选中块 |

| `text-primary` | `#1D1D1F` | 标题、主要内容 |
| `text-secondary` | `#66666C` | 说明、日期、数量、次级信息 |
| `separator` | `#E0E0E0` | 分组、列表、底栏分隔线 |
| `separator-soft` | `#F0F0F0` | 弱分隔 |
| `brand` | `#0066CC` | 主按钮、可操作文字、选择、当前筛选 |
| `photo-selection-mask` | 白色，约 26% 不透明度 | 选中照片蒙版，搭配右下蓝底白勾 |
| `brand-tint` | `#EAF3FF` | 次要蓝色操作面、筛选激活面 |
| `disabled-bg` | `#EEEEF1` | 禁用按钮背景 |

暗色模式使用同语义的系统动态颜色，确保文字和状态对比度；不得在暗色模式把危险操作弱化为普通灰色。系统确认框、权限框沿用系统配色。

### 3.3 字体与圆角

使用平台系统字体和系统无障碍字号缩放。下列字号是默认字号基线，不得锁定字体缩放。

| 角色 | 默认尺寸与字重 |
| --- | --- |
| 相册页导航标题「实况转静态」 | 21，半粗体 |
| 结果摘要 | 24，半粗体，可换行 |
| 弹层标题 | 20，半粗体 |
| 日期标题 | 17，半粗体 |
| 主按钮 | 16，半粗体 |
| 普通操作、分段、正文 | 14；操作/分段中等，说明常规 |
| 已选张数 | 16，半粗体，数字等宽 |
| 文件名、结果标签 | 13 / 12，半粗体 |
| 空间估算、可见数量 | 13 / 12，常规，估算数字可加重 |
| 次级信息 | 12，常规 |

应用内填充按钮的圆角以 12 为基线，包括图库保存、筛选应用、查看副本和移除前核对的底部主动作。相册分段外框圆角 11，选中块圆角 8。照片单格圆角约 3，网格外缘约 4。结果标签、日期把手和日期浮标使用胶囊形。弹层和预览分别使用 25 和 18 的圆角参考。

## 4. 页面结构与文案

### 4.1 相册首页

页面从上到下：

1. **固定导航栏**：页面标题「实况转静态」。首页不出现「本次结果」入口。结果通过完成保存后的流程到达；如需恢复未完成批次，使用状态明确、可理解的恢复入口，不混入普通浏览工具栏。
2. **相册控制区**。依次放置「按日 / 全部」「只看已选」「筛选」。普通字号下排列为一行，分段宽度以原型的 156 为参考；大字号下允许换行。
3. **元信息行**。显示可见照片数、当前类别或收藏保护状态。首次使用可提示「横划多选 · 长按预览」，完成一次选片或预览即收起。有限权限时显示「管理照片权限」。选中数量由底栏展示。
4. **按日分组**。日期旁显示可见数和已选数。右侧三态复选框显示未选、部分选中、全选，右缘对齐第五列，点击区至少 44 × 44。部分选中时再次点按全选当天可见照片，已全选时点按全部撤选。日期未知时显示「日期未知」，需要时补年份。
5. **五列照片网格**。左上叠加实况标识，右下叠加选择状态。选中后保留照片可辨认度，使用浅蒙版和蓝底白勾。收藏标识低调显示，云状态由系统可确认的数据决定。
6. **固定底部操作区**。选中后显示「已选 N 张」和「保存后，原件仍在相册」，下一行显示空间估算，下方为「取消选择」和「保存静态副本」。存在被筛选隐藏的选择时，主按钮显示「核对后保存」。清空选择后收起底栏，并禁用「只看已选」。

空间估算显示 iOS「移除原件后预计节省」或 Android「清空回收站后预计节省」。已知时显示约数，部分未知时显示已知下限和未知张数，完全未知时显示「可节省的空间暂未知」。同一屏宽和字号下，计算中与结果态使用稳定的高度，保存按钮和当前照片位置需要保持稳定。

### 4.2 按日 / 全部与筛选

- 默认使用「按日」。切换「按日 / 全部」只改变展示方式，不清空任何有效选择。
- 「按日」以拍摄日期从新到旧分组；「全部」按同一排序连续展示。两种模式均用相同的五列网格和同一照片卡片。
- 轻点单张照片任意位置切换选中状态；不要求精确点中角落的勾选标记。
- 长按约 0.45 秒打开实况预览，长按不改变选中状态；开始滚动时取消长按。预览自动播放一次，关闭后回到原滚动位置并保留选择。
- 实况预览以两端原有的沉浸式效果为准。保留实况角标，点暗幕退出。Android 保留从缩略图展开及收回的过渡，iOS 保留照片原有的适配与转场。
- 横划可一次选择起点与终点之间的照片。从未选照片起手加选，从已选照片起手撤选。范围按本次手势起点的选择状态确定，左右方向遵循同一规则；手势内折返按新终点重新计算。纵向手势用于浏览，只看已选时可逐张撤选。
- 快滚使用右侧白色双箭头胶囊。滑动浏览时显示，拖动时列表和日期浮标实时跟随，松手后浮标消失，空闲约 1.35 秒后把手淡出。只有显示中的把手参与命中，其余区域由照片网格响应。只有图库可滚动时才启用快滚。
- 「只看已选」在选择数大于零时可用。清空或取消最后一张后立即退出该模式，并禁用此按钮；不可留在空的筛选结果中。
- 「只看已选」直接在相册工具栏操作。筛选弹层包含「保护收藏」，iOS 另有按内容筛选。收藏保护默认开启；iOS 在用户主动识别后提供「全部类别 / 含人物 / 风景 / 文字 / 其他 / 未确定」。
- 筛选修改先进入草稿。「显示 N 张照片」显示应用后的可见数，点击后一次提交；关闭、返回或取消时丢弃草稿。开启收藏保护将撤选已选收藏时，提交前说明张数，提交后只撤销受保护的项。其余仍有效的选择保留；清除类别和「只看已选」时保留收藏保护。识别作业、权限和设置是否跨启动保留沿用各端现有行为。
- 若当前筛选隐藏了仍被选中的照片，在相册控制区下方显示提示「筛选藏起了 N 张已选照片，保存前可核对。」主按钮改为「核对后保存」并进入完整清单，避免用户误以为隐藏项目不会被保存。
- 读取整库期间，已展示的照片应可立即选择、按日选择和保存。日期尚未识别完整时，批处理按钮文案明确限定为已加载范围；之后加载的照片不自动加入本次选择。

### 4.3 保存进度

点主按钮后冻结本次有效选择，并清空相册中的临时选择；当前运行的转换任务独立记录。显示独立进度页面：

- 标题「正在保存副本」，展示当前照片、当前阶段、已完成数量和进度条。
- 阶段按真实工作更新：准备、写入、回读核验。不得用虚构或含混的「保存批次结束」提示替代实际结果。
- 清楚提示原件仍保留。发生单项失败时继续其余可处理项，并在结果页逐项说明。
- 结束进程后，未提交的照片选择从空状态开始；已提交任务是否可继续，依据持久化操作记录对账，不能恢复旧选择作为待保存照片。

### 4.4 结果页

页面顺序为导航、结果摘要、查看静态副本、原件处理、逐张结果，以及适用的处理入口或详情。左上「返回」和系统返回均可返回相册。

- 摘要准确显示已保存副本数与原件状态。没有可确认副本时显示「本次未确认静态副本」。原件状态待系统确认时明确写待核对。
- 有可查看的副本时，使用主要按钮「查看静态副本」。独立的「原件处理」区域提供红色核对入口或 Android 恢复位置。iOS 用「移除原件前核对」，Android 用「移入回收站前核对」。
- 所有项目按本批顺序进入同一份「逐张结果」。待核验、失败、已跳过和已核验都在各自的只读行显示状态和原因。iOS 的导出封面、Android 的中断续跑及两端核对或诊断入口在适用时继续可达。
- 「查看静态副本」打开本批副本列表并按资产 ID 读回实际副本。页面提供系统相册路径。
- 每个状态都用文字标签并辅以颜色。结果标签允许在大字号下换行；长文件名和失败原因允许折行。
- 返回后保留任务记录和恢复入口；已提交批次的勾选保持清空。

状态文案：

| 内部状态 | 用户标签 | 用户可见含义 |
| --- | --- | --- |
| `verified` | 已核验 | 已回读确认静态副本，可进入原件复核 |
| `previewOnly` | 保留原件 | 副本已保存，但原件不参与本次移除 |
| `pending` | 待核验 | 尚无法确认副本，原件保留 |
| `skipped` | 已跳过 | 显示跳过原因，原件保留 |
| `failed` | 保存失败 | 未确认副本，原件保留 |
| `retained` | 复核未通过 / 原件仍在 | 根据系统返回显示原因，原件保留 |
| `removalPending` / `NEEDS_CHECK` | 待核对 | 系统操作结果尚无定论，可继续核对原件状态 |
| `removed` / `IN_TRASH` | 原件已移除 / 已移入回收站 | 系统已确认对应操作，静态副本保留 |

### 4.5 查看副本和系统相册

「查看静态副本」进入本批静态副本列表。每项提供副本预览；列表或页头注明系统相册位置。

| 平台 | 相册位置说明 |
| --- | --- |
| iOS | 照片 App → 相簿 → 实况转静态 |
| Android | 系统相册 → 图集 → LiveToFrame |

在不具备官方可靠指定相册深链的系统上，优先在应用内列出本批副本并展示上述路径。系统图库启动能力可用时，可以打开图库应用；不可声称一定落到指定相簿。应用内列表必须仍可使用。

### 4.6 核对并移除原件

- 从结果页红色入口进入「移除前核对」弹层。仅列出已核验副本且通过当前权限、收藏保护、原件状态、相册归属和格式复核的实况原件。
- 显示将处理的原件数、静态副本已核验数和估算空间。明确提醒 iCloud/云同步或 Android 回收站的影响。
- 底部固定危险操作按钮。iOS 使用「复核并继续移除（N 张）」，Android 使用「移入回收站（N 张）」。清单独立滚动，取消最后一张时禁用按钮。
- 用户继续后再次读取源照片与副本状态；只把通过核对的原件提交系统。任意不确定、保存失败、取消或权限不足均保留原件并显示实际状态。
- 最终确认必须使用平台系统 API 和系统确认 UI。iOS 通过系统照片删除确认；Android 通过系统媒体回收站/删除请求。不得自制一个看起来像系统的确认框取代系统授权。
- 用户取消系统确认后回到结果页，原件保持原样，可再次发起核对。

## 5. 空状态、权限、加载和错误

| 场景 | 标题/说明 | 主要操作 |
| --- | --- | --- |
| 尚未授予照片权限 | 「选择要访问的照片」；说明授权后可浏览允许访问的实况照片 | 「选择照片权限」并由系统展示授权 UI |
| 权限被拒绝或受限 | 说明当前授权范围及如何管理 | 「打开设置」或「管理照片权限」 |
| 正在读取 | 「正在读取相册…」；用占位图，不闪现错误空态 | 已加载内容仍可操作 |
| 无可用实况照片 | 「没有可用的实况照片」 | 「管理照片权限」或简短拍摄提示 |
| 当前筛选无结果 | 「没有符合筛选的照片」 | 「清除筛选」 |
| 只看已选且空 | 正常流程应自动退出此模式；不得呈现死路 | 恢复相册列表 |
| 静态副本待核验/保存失败 | 显示具体项目和失败/核验原因 | 按平台能力提供重新核验或「导出可读封面」 |

权限、照片选择器、相册访问和系统删除确认必须由平台官方系统 API 呈现。局部权限下只能读取用户允许的资产，并提供可到达的权限管理入口。

## 6. Android 与 iOS 系统适配边界

以下情形必须尊重系统行为，允许与原型在外观上不同：

1. 状态栏、顶部/底部安全区和返回手势。
2. 系统照片权限申请、iOS 照片选择器、Android 系统媒体选择器。
3. iOS 删除资源确认与 Android 回收站/删除请求确认。
4. 系统图库打开、文件导出/分享、系统设置跳转。
5. 系统字体、辅助功能、触控反馈和动态颜色。

以下属于应用自身设计，两端保持一致：页面层级、控件顺序、文案、字体层级、间距、五列网格、筛选方式、选择状态、底栏、卡片/按钮形态、状态色、危险操作层级、结果行只读规则。不能因为 Android 的返回键存在就增加「返回相册」歧义文案；显式返回按钮依然用箭头并提供无障碍名称「返回」。

## 7. 无障碍与适配

- 普通触控目标至少 44 × 44 dp/pt；日期快滚按第 3.1 节的竖向拖动热区验收。网格照片整个单元可以点选。
- 所有按钮有动作名称和当前状态；「只看已选」需读出禁用态/开关状态；照片需读出日期、选择状态和实况属性。
- VoiceOver/TalkBack 能通过独立操作预览实况照片和关闭预览，不依赖长按手势。
- 弹层开启后焦点移至标题；关闭后回到触发控件。进入结果页时先播报摘要。
- 支持系统字体放大。窄屏、超大字号下允许纵向增加高度和换行；不截断危险操作、日期或状态原因。固定五列仍保持，避免为了容纳标题临时变成不同列数。
- 颜色不是唯一状态信号；绿色、琥珀色和红色胶囊必须保留对应文字。
- 启用减少动态效果时减少缩放和位移动画；预览实况仍须由用户明确触发。
- 键盘、返回键、系统返回手势和弹层关闭的导航结果一致，焦点不能丢失。

## 8. 开发验收清单

### 视觉

- [ ] iOS/Android 的相册页标题均为「实况转静态」，位于「按日 / 全部」上方。
- [ ] 两端普通组件使用相同 token、尺寸和排序；仅系统接管界面出现平台差异。
- [ ] 相册网格在常见手机宽度下恒为五列、方形、4 间距。
- [ ] 主按钮高度至少 46、圆角约 12；普通触控目标至少 44 × 44。
- [ ] 左右边距一致、当天复选框和第五列右缘对齐；把手显示和隐藏时照片布局一致。
- [ ] 颜色含义统一，核对并移除原件的入口是红色。
- [ ] 文字随系统字号放大且可换行，底栏和弹层不遮挡主要动作。

### 交互

- [ ] 选择、按日选择、按日/全部切换、筛选往返后，选择集合和计数一致。
- [ ] 选择为零时「只看已选」不可点；取消最后一张后自动退出只看已选。
- [ ] 「已选 N 张」仅展示数量，点按无动作；「取消选择」清空当前临时选择。
- [ ] 点按选中与长按预览互斥；关闭预览恢复滚动位置和选择状态。
- [ ] 左右横划可加选和撤选，折返结果可预测，纵向滚动与快滚不触发误选。
- [ ] 快滚拖动时日期和列表跟随，淡出后第五列与日选可正常点按。
- [ ] 筛选可预览张数；取消保持原状态，应用后隐藏选择数与完整清单一致。
- [ ] 窄屏在估算计算中、部分未知和全部未知之间切换时，保存按钮和当前照片位置稳定。
- [ ] 只有一份逐张结果，状态与原因在各自的只读行展示，查看副本和原件处理入口可达。
- [ ] 首页没有「本次结果」入口；结果页返回控件统一为「返回」。
- [ ] 保存成功提交后选择清空；应用重启不恢复未提交选择。
- [ ] 只有核验通过且再次复核通过的原件才进入平台系统确认。
- [ ] 系统确认取消后原件保留；结果只报告平台可证实的状态。
- [ ] 静态副本列表准确对应当前批次，并显示系统相册位置。
