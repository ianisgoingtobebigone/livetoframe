## 实施顺序与代码落点

1. **图库和手势**。iOS 在 [LibraryView.swift](../ios/LiveToFrame/LibraryView.swift) 的 `galleryControls`、`SelectablePhotoTile`、`PhotoGalleryScrollArea` 和 `GalleryRangeGesture` 调整。Android 在 [GalleryScreen.kt](../android/app/src/main/java/app/livetoframe/personal/GalleryScreen.kt) 的 `GalleryControls`、`GalleryTile` 及 [GalleryRangeSelection.kt](../android/app/src/main/java/app/livetoframe/personal/GalleryRangeSelection.kt) 调整。iOS 日期覆盖使用现有 `GalleryDateScrollbar`，Android 使用 [GalleryDateScrollbar.kt](../android/app/src/main/java/app/livetoframe/personal/GalleryDateScrollbar.kt)。
2. **筛选和底栏**。iOS 的 `filterSheet`、`actionBar`、`StorageEstimateLine` 与 Android 的筛选弹层、`Dock`、`PrimaryAction` 承接 UI。复用 `LibraryModel` 与 `GalleryModel` 的收藏处理和有效批次逻辑；草稿只在展示层，关闭操作无需回滚业务数据。提交前后检查可见集、已选集和实际保存集。
3. **结果与核对**。iOS 的 `resultsScreen`、`resultMessage` 与 Android 的 `BatchResults` 负责呈现。沿用真实副本 ID、写入回读、原件复核、任务恢复和系统确认。把示例中的界面布置接到原生流程，系统返回状态不明时继续展示「待核对」。
4. **验收与回退**。实施前留出两端 UI 文件的可恢复基线；分图库/筛选与结果阶段验收。确需回退时恢复该轮 UI 改动，保留任务记录、相册数据和原型。若使用真机验证原件操作，采用可舍弃的测试照片。

## 2026-11-22 逐屏视觉对照

逐屏查看 iPhone 13、OPPO 和已确认 HTML。比较时以应用内容区为基准，系统状态栏、安全区和实际照片各用设备上的内容。

| 页面 | 真机与 HTML 的可见差异 | 本轮调整 |
| --- | --- | --- |
| 相册 | 原生日期组之间更紧；具有相同日期的照片和下一组标题之间层级偏弱。 | 两端在日期组切换处补间距，沿用五列、日选位置和快滚覆盖层。 |
| 选中底栏 | iOS 两颗按钮等宽，HTML 和 Android 的保存入口更宽。数值、说明到按钮的间距也有出入。 | iOS 按 2:3 分配按钮宽度，大字号时纵向排列。两端调整数量、估算与按钮的间隔。 |
| 筛选 | iOS 固定高度与大开关产生较多空白，Android 有额外的拖拽条与底部留白。 | iOS 根据内容和字号设定初始高度，使用 43 × 26 的开关。两端对齐标题、关闭按钮、底部动作和收藏撤选提示。 |
| 实况／静态预览 | 原生预览缺少 HTML 中的文件名、可见关闭和重播入口。 | 两端采用同样的标题、照片、状态和动作布局。实况重播复用各自的真实播放器。 |
| 保存进度 | Android 标签、标题和进度条间距偏紧，轨道有默认的末端圆点。 | 对齐标题节奏、蓝色进度与浅灰轨道，继续读取实际保存阶段和进度。 |
| 本次结果 | Android 的副本主按钮缺图标，两端的逐张数量与标题处于同一级，状态标签略小。 | 增加副本图标，标题与数量用不同字重和字号，状态标签调到约 12。 |
| 静态副本 | 原生批次标题为 24，HTML 为 34。 | 两端将批次标题调到 34，保持三列副本和相册位置说明。 |
| 原件核对 | iOS 的说明分散且单张时留白大；Android 的估算缺少底板。 | 收紧 iOS 单张面板，将选中与估算放进摘要，使用浅琥珀底提醒 iCloud 同步。Android 用浅底突出回收站估算，并保留平台恢复说明。 |

复核使用改版前后的真机画面和同宽 HTML 页面。两端完成构建、覆盖安装并启动，现场查看了新版筛选、实况预览、保存进度、结果、副本和原件核对。收尾修订后，再用单张实况确认两端结果均为「已核验」，并检查 iOS 核对弹层和 Android 进度条。原件核对停在应用内清单。

### OPPO 同宽复核

以 OPPO 实际的 360 dp 内容宽度对照 360 px 的 HTML Android 页面。此次调整了 Android 标题与状态文字的字距、行高，收紧了图库顶部、筛选面板和结果页动作行，并补齐了预览的背景模糊。以单条可复核记录的结果页截图测量，原件处理卡片从约 106 dp 收到 87 dp，HTML 对应卡片约 90 px。OPPO 覆盖安装后，复查了图库、选中底栏、筛选、实况预览和单张保存结果，逐张状态显示「已核验」。
