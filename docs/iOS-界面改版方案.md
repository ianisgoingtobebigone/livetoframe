# LiveToFrame iOS 界面改版方案

状态：原型已确认，等待实施。  
范围：iPhone、现有 SwiftUI 项目，最低部署目标 iOS 17。  
对照：[双平台 HTML 原型，切换到 iOS](LiveToFrame-Prototype.html) · [跨平台视觉与交互设计规范](跨平台视觉与交互设计规范.md) · [原产品与技术方案](../实况转静态-产品与技术方案.md)

新版原型在有勾选时启用「只看已选」。筛选隐藏了已选照片时，可通过「核对后保存」打开完整清单。逐张结果展示状态，预览集中在「查看全部静态副本」。结果页左上角为「返回」，首页去掉「本次结果」入口。

## 目标与边界

用户在这里要决定哪些照片只保留封面。偶尔处理一张照片的人可以直接选择并保存。整理整趟旅行照片的人可以按日期成批选择，保存后逐张确认，再决定是否移除原件。首页服务于找照片和选择，结果页服务于确认静态副本、处理异常和决定原件去留。

本轮实施覆盖首页、筛选、实况预览、已选清单、处理进度、结果、静态副本查看和移除前核对。沿用 PhotoKit 的读取、写入、回读、原件复核、系统确认及「文件」导出。转换算法、画质与元数据校验、相册迁移、持久化格式、后台处理和 Android 不在改版范围内。任务恢复沿用现有日志。

HTML 是手机界面和交互的参照。正式版以用户授权的照片、真实的处理进度和系统确认界面为准。原型中的示例相册、桌面说明栏、模拟权限/删除弹窗和示例容量仅用于演示。

## 一、按用户流程实施

| 环节 | 现有落点 | 改动 |
| --- | --- | --- |
| 浏览与筛选 | `LibraryView.libraryContents`、`PhotoDateGroupViewData` | 去掉首屏介绍卡。默认「按日」，保留「全部」，按日期从新到旧。主区域固定五列缩略图。筛选弹层初始 340 pt，可展开并支持滚动。把保护收藏、只看已选和内容分类收进「筛选照片」半屏弹层。在有限权限下保留「管理访问」，即使已有结果也可从筛选或权限状态行进入。 |
| 选择与预览 | `LibraryView.photoButton`、`PhotoTile`、`LiveContextPreview` | 点按切换选择。长按沿用现有互斥手势和 `PHLivePhotoView`，准备好后自动播放一次。沿用缓存、按需加载和取消请求，预览关闭后回到原滚动位置。 |
| 批次核对与保存 | `LibraryView.actionBar`、`LibraryModel.selection` / `sequence`、`convertSelection(excludingFavorites:)` | 底部操作区在主按钮内显示所选张数，在其上方显示条件性的空间估算。保存按钮旁提供「取消选择」，一次清空当前勾选。存在被筛选隐藏的有效已选项时，主按钮先进入清单，清单内仍可撤选，最后由「保存 N 张静态副本」提交。 |
| 保存进度 | `LibraryModel.progress` | 进入独立处理界面，显示现有实际状态或第 X / N 张。只有拿到可信进度才显示可计量进度条，否则用系统不定进度。保存启动后禁止重复提交及修改批次。 |
| 结果与副本 | `LibraryView.resultsSheet`、`ConversionResultRow`、`ConversionOutcome` | 首屏给出已确认副本数和原件状态。其下依次显示「查看全部静态副本」、红色「核对并移除原件」及只读的逐张状态。左上「返回」回到首页。 |
| 移除前核对 | `LibraryModel.readyToRemove`、`removeOriginals()`、`PhotoConverter.prepareRemoval` | 由结果页打开半屏核对清单。点击「继续移除 N 张原件」才发起现有复核。不通过的原件保留，只有通过复核的子集提交给系统确认。返回结果后根据实际返回值更新移除数量。 |

## 二、数据与状态的接法

### 选择和筛选

- 统一派生实际保存批次。以 `sequence` 保留现有点选顺序，使用 `ConversionSafetyPolicy.conversionIDs` 处理收藏保护，并核对当前可访问的资产。主按钮数量、已选清单、空间估算与保存入口使用相同 ID 集合。最终提交仍由 `convertSelection(excludingFavorites:)` 执行校验。
- 展示范围在可访问和收藏保护的基础上应用类别与「只看已选」。切换「按日 / 全部」、类别或仅看已选时保留有效选择。当天操作以当前可见照片为范围，该范围已全选时显示「取消当天」。空筛选只重置类别和「只看已选」，保留收藏保护和已有选择。
- 保护收藏默认开启。重新开启时，从本轮 `selection` 和 `sequence` 同步撤销已选收藏，提示撤选数量。相册刷新或授权变化导致照片离开批次时同步刷新清单、数量和估算。若已打开清单，保存以刷新后的可见清单为准。
- 沿用现有端侧分类。用户主动发起，可用分类结果增量回填。当前 `classifyAssets()` 只处理尚未分类的照片，有新增待处理时显示「继续识别」，全部处理后显示「已识别」。保留「未确定」类别及本机读取限制。

### 空间估算与执行

- 复用 `estimateText(for:title:)` 的已知、部分已知、估算中、未知语义，必要时仅调整展示结构和文案。首页估算对应实际保存批次，移除核对页估算对应可提交复核的候选。当前实现仅在 iOS 27 及以上按需读取配对视频的可用大小，估算过程不主动下载云端资源。界面只说明移除后可能减少的动态资源，不报告已经释放了多少本地或 iCloud 空间。
- 用户每次明确点保存都走现有新一轮写入。同一张实况保留原件时可以重新选择并再生成副本。结果关闭后与返回相册的 UI 状态变更分别处理，避免把返回键或弹层关闭当作保存、放弃批次或移除操作。
- `LibraryView` 负责导航和弹层，`LibraryModel` 继续负责授权、选择、结果及任务状态。导航承接当前 `showResults` 的职责，避免导航入栈与旧结果弹层同时触发。进度、结果和导出要围绕同一在途任务，保留 `fileExporter` 和授权失败的现有处理。

### 结果与真实相册

- 已确认静态副本集合为 `verified`、`previewOnly`、`retained` 和 `removed`。可提交移除前复核的候选从真实状态派生，交给 `PhotoConverter` 重新核验副本、原件、元数据、相册归属和删除权限。
- 「查看静态副本」优先用本轮保存或恢复时获得的 `ConversionRecord.replacementID`，按当前权限通过 `PhotoConverter.fetch` 读取实际写入的静态资产。可给 `ConversionOutcome` 增加可选展示字段，覆盖正常写入和日志恢复，并在移除状态变更时保留该字段。以该 ID 请求预览，继续复用项目已有的图片加载方式。原件缩略图只作结果行识别，不能冒充静态副本。
- 副本受权限或可见性限制时，显示简短说明和核对办法。只有实际存在输出相册时指向系统「照片」中的「实况转静态」，否则按当前可访问状态提示去「最近存储」检查或管理照片访问。保留 `pending` / `failed` 的「导出封面到文件」入口。导出成功仍保留原件，结果状态继续按相册回读判定。
- 恢复路径目前会把恢复成功映射为 `verified`，而正常转换会将 `usedCurrentRendition == true` 映射为 `previewOnly`。实施时统一这两个展示映射，避免已经明确不参与移除的副本出现在核对页。保留 `prepareRemoval` 的底层保护。
- 用户取消系统确认后维持尚未移除的已核验项及已保存副本，只更新真实发生的状态。全批复核未通过时留在结果页，不出现系统删除请求。若系统已收到移除请求，但后续回读或记录失败，提示用户到相册确认原件与副本的实际状态。

## 三、建议实施顺序

1. **首页、筛选、手势。** 在 `LibraryView.swift` 改布局和导航入口，先用现有惰性网格、缩略图缓存及长按预览跑通空、有限权限、有照片三类状态。把重复样式提取成少量 SwiftUI 共用常量和组件。
2. **已选清单与保存。** 接入批次派生、撤选、隐藏项提示及进度。先验收「单张直接保存」和「跨日加筛选的批量保存」，检查可见数、选中数、顺序和估算。任何时候只有一个保存入口能发起同一次任务。
3. **结果和副本。** 组合顶部摘要、逐张状态和「返回」导航，再接本轮真实副本读取、受限权限降级和文件导出。现有诊断保留在折叠区。
4. **移除和异常。** 最后接核对弹层、真实复核和系统确认。复测取消、部分不通过、全批不通过和成功后结果回写。
5. **构建、真机验收。** 先通过 [iOS 工程](../ios/LiveToFrame.xcodeproj) 编译已有目标并运行现有安全测试，再在已授权的测试照片和设备上实测。若手动新增 Swift 文件，确认 Xcode 目标包含它，并保持 `ios/project.yml` 与 Xcode 工程的源文件设置一致。

## 四、验收与回退

| 验收层级 | 核对项 |
| --- | --- |
| 编译与回归 | iOS 17 部署目标可构建。运行 `ConversionSafetyTests` 并记录实际结果，覆盖收藏排除、可移除记录条件、相册归属和中断日志。若改了恢复状态映射或批次派生，补对应回归。 |
| 视觉与输入 | 在紧凑宽度和 iPhone 13 检查固定五列、筛选弹层、顶部与底部的背景透出、底部安全区、长文件名、弹层滚动及大字号。VoiceOver 能读出选中状态、预览动作、结果标签和错误说明。按日与全部互切保持选中，快速滚动、长按与关闭不误选。结束进程后重开，勾选、张数与估算回到空状态。浅色对照 HTML，暗色检查可读性。 |
| 相册与选择 | 实测完整/有限/拒绝权限、授权缩小和空相册。跨日期选择后切换类别，清单张数与实际保存数一致。重新开启保护收藏后，受保护的选项从清单移除且不会写入。 |
| 保存与失败 | 用可舍弃的普通实况和一组异常样本，核对真实封面、文件名、相册内新增资产和原件是否仍在。验证重复显式保存、部分成功、待核验、失败及导出。若某个异常无法稳定制备，可用开发态受控数据验证界面，单独记录真机业务验证仍缺的证据。 |
| 移除 | 先用可舍弃样本取消系统确认，核对副本与原件均保留。再复测成功及部分复核失败，只对通过复核的原件发起系统确认。核对相册中仍有可打开的静态副本，结果只标记真实完成的原件。iCloud 和本机占用如需验收，按各自状态实测。 |

实施前为会修改的 Swift 文件和工程配置留可恢复基线。当前目录没有 Git 元数据，可先做源码备份。回退时恢复本次 UI 与展示层改动，保持原有 bundle ID 和日志位置，原型仍可用于对照。关闭界面或回退代码不会恢复相册数据，真机删除测试只使用专门准备的可舍弃样本。
